# Glory 榮耀 · 投影控制台（V2.3）

單機雙螢幕的教會投影控制台。品牌名為 **Glory（榮耀）**，主介面採黑金高對比配色；V1.0 已完成放映核心（M1 四項驗證），V1.1 在此之上加入**素材切換**：主 PPT 之外可再導入詩歌／經文／其他簡報，逐頁匯出成圖，一鍵切換播出，切換過程不中斷主放映。

> 開源授權：MIT License。原始碼以 Windows WPF／.NET 8 建置；主 PPT 放映需 Microsoft PowerPoint 2016 或更新版本。
>
> 2026-11-25 修正：放映期間勾選「控制台不主動搶焦點」時，不再對主視窗套用 `WS_EX_NOACTIVATE`。控制台仍可用滑鼠點擊取得焦點，方向鍵可正常翻頁；程式只在放映開始時把前台交還放映視窗，不主動搶焦點。

## 建置

需求：Windows 10/11 x64、.NET 8 SDK、Visual Studio 2022 或更新版本（含 WPF 工作負載）。

```powershell
dotnet restore ProjectionManager.csproj
dotnet build ProjectionManager.csproj -c Debug
dotnet run --project ProjectionManager.csproj
```

Release 自包含發佈：

```powershell
dotnet publish ProjectionManager.csproj -c Release -r win-x64 --self-contained true
```

安裝包使用 Inno Setup 編譯 `installer\Glory_Projection_Console_V2.3_20261121.iss`；`installer\prereq` 內的 WebView2 離線安裝程式不進 Git，需另外放置。


## 品牌與主題

- 視窗標題為「Glory 榮耀 · 投影控制台」，標題列左側為金色 G／光圈 Logo，右側為「設定」入口。
- 預設主題為**黑金**（純黑背景、金色強調、奶油金文字）；可在設定中切換為舊版**深灰青綠**或**暖白背景**，切換後立即套用到主控制台，重新啟動仍保留。
- 設定頁集中較少用的項目：三種主題、主 PPT／素材的選檔起始資料夾，以及設定檔、素材索引、素材快取、預覽暫存的實際路徑與「開啟資料夾」。
- 應用程式圖示與工作列圖示為 `Assets/glory.ico`；Logo 原始檔為 `Assets/glory_logo.png`。`AssemblyName` 仍保留 `ProjectionManager`，避免既有測試腳本與 `ProjectionManager.exe` 路徑失效。

V1.0 已驗證的四件事，仍是本程式的基礎：

1. 以 Raw Input 認出**講員的翻頁筆**，與操作員的鍵盤區分開；
2. 以 **COM 直接推進** PowerPoint 放映，不需要放映視窗取得焦點；
3. 以 **ClipCursor 鎖住鼠標**在作業螢幕，並防止一次按鍵前進兩頁；
4. **控制權在操作員與講員之間換手**：只切換狀態標示、記錄交出頁，不鎖定任何一方。

需求文件見同目錄的《教會多源投影管理系統_需求規格說明書_V1.0.docx》。V1.0 覆蓋 FR-DSP-01 至 FR-DSP-03、FR-SHW-01 至 FR-SHW-03、FR-INP-01 至 FR-INP-05、FR-OPS-01、FR-CTL-01 至 FR-CTL-06；V1.1 覆蓋 FR-MAT-01 至 FR-MAT-04、FR-SWH-01、FR-SWH-02、FR-DSP-04。

## V1.1 素材切換：新增了什麼

### 兩個投影源，一鍵切換

左欄是**投影源清單**：第一項固定是主 PPT（PowerPoint 原生放映），其餘是導入過的素材。點卡片即切換播出，正在播出的那張有青綠色框與「播出中」字樣。

**主 PPT 也有畫面預覽**：放映中，控制台會把「當前頁」用 `Slide.Export` 匯成一張 1024×576 的圖顯示在「播出中」框裡，右上角標示「第 n / N 頁 · 靜態預覽」。翻頁筆或操作員一翻頁就跟著換圖；它只是靜態截圖，**動畫與轉場仍然只在投影幕上播**。實測放映中匯出可行（約 0.2–1.3 秒，PowerPoint 忙時較慢），不會中斷放映。

**主 PPT 進入素材、再回主 PPT 時，PowerPoint 的放映從不停止**——只是被蓋住。回來時頁碼停在原來那一頁，動畫與轉場照原來的方式繼續。

點下方數字縮圖可直接跳頁。跳頁前會先核對放映的實際頁數，超出範圍只寫日誌、不中斷放映；先前「點頁數報 GotoSlide 14 超出 1–13」的例外已修（原因是縮圖按鈕的閉包抓到迴圈結束後的值）。

### 素材庫分組

左欄的素材以「分組」組織：主 PPT 卡片之下，每一組有一個組標題（例如「未分組　4」「詩歌　1」），標題下面是該組的素材卡片。

- 第一次啟動時只有一個預設分組「未分組」；舊版索引裡沒有分組資訊的素材，載入時自動補到這一組，不會消失。
- 按「＋ 新增分組」輸入名稱即新增一組。點任一組標題，該組成為**目前分組**，之後導入的素材都放進這一組（日誌會寫明放進了哪一組）。
- 對組標題按右鍵可「重新命名分組」或「刪除分組」。刪除時組內素材移到「未分組」而不會被刪掉；預設組不可刪除。
- 導入素材**不會自動切換播出**，只會出現在左欄，要自己點卡片。

### 素材導入：單檔、整批、支援格式

左下三顆按鈕：

| 按鈕 | 作用 |
|---|---|
| ＋ 素材　PPT／圖片 | 一次選一份或多份檔案，導入目前分組 |
| ＋ 加入文件夾（整批） | 選一個資料夾，把**這一層**的支援檔案全部導入目前分組（不改子資料夾） |
| ＋ 新增分組 | 新增素材庫分組 |

目前支援的格式：

| 類型 | 副檔名 | 導入方式 |
|---|---|---|
| PowerPoint 簡報 | `.pptx` `.ppt` `.ppsx` `.pptm` | 用 PowerPoint 無視窗開啟，逐頁 `Slide.Export` 成 PNG，每頁一張 |
| 圖片 | `.png` `.jpg` `.jpeg` `.bmp` `.tif` `.tiff` | 直接複製進素材資料夾，一張一頁 |

導入結果會統計「成功／略過／失敗」：重複的檔案（同名且已導入過）與不支援的格式算略過，個別檔案出錯算失敗，都不影響其他檔案。資料夾整批導入時，`.txt`、`.pdf` 這類不在上表的檔案會被略過，日誌會寫「略過 N」。

簡報轉圖的解析度取**目標投影螢幕的實際像素**（還沒選螢幕時用 1920×1080）；資料夾與簡報路徑只記在索引裡，原始檔案不會被搬動或修改。「重新匯出」用同一份原始簡報再轉一次；圖片素材不需要重新匯出。「移除」只刪索引與圖片資料夾。

已實測（本機，單螢幕）：新增分組「詩歌」→ 匯入一張 PNG → 組標題變「詩歌　1」；整批導入含 2 張圖與 1 個 txt 的資料夾 → 「成功 2、略過 1」，預設組由 2 變 4；重啟程式後分組與計數都還在。

### 翻頁筆在素材源時翻素材頁

翻頁筆仍只認綁定的那支。播出源是素材時，筆的下一頁／上一頁直接翻素材頁，**主 PPT 的頁碼不會被動到**；回到主 PPT 時，講員從他原來那一頁繼續。

### 縮圖條、預備預覽

中欄下半是縮圖條：素材顯示每頁縮圖，主 PPT 顯示頁碼格（點一格即 `GotoSlide` 跳頁）。上半右側「播出中」是素材當前頁，左側「預備」是下一頁，切頁前可以先看一眼。

### 熱插拔

接上／拔掉投影線、改解析度時，Windows 會發 `WM_DISPLAYCHANGE`。程式收到後重新列舉螢幕、更新下拉選單，並把放映視窗與素材視窗依新座標重新定位。

### 與需求文件不同的地方（需你知道）

文件 4.7 寫的是切換時把 PowerPoint 放映「移出投影螢幕」（讓位）。實作改成**遮蓋＋置頂**：素材視窗以 `WS_EX_TOPMOST` 加 `WS_EX_NOACTIVATE` 直接蓋在放映視窗之上，PowerPoint 完全不動。

原因：放映視窗會自己搶回原位（V1.0 就遇過，得靠 3 秒校正窗壓住），把它移出螢幕再移回來，等於跟 PowerPoint 爭圖層，容易出現半秒空白或位置錯亂；蓋住則沒有這個競態。對觀眾而言兩者畫面相同，對講員而言翻頁筆控制的是「當前播出源」，也相同。若之後確實需要「讓位」（例如要省 GPU 合成成本），再改回文件寫法。

### 已知限制

1. **匯出時界面會卡住**：轉圖是同步 COM 呼叫（約 0.3–1 秒／頁），匯出 35 頁的簡報期間控制台沒有回應，這是正常的，等日誌出現「素材已導入」即可。V1.2 之後可移到獨立 STA 執行緒。
2. **素材是靜態圖**：只保留版面、文字、圖片，**不保留 PPT 動畫**。素材若需要逐項出現的動畫，得改用雙 PowerPoint 實例疊放（切換延遲 2–3 秒），尚未實作。主 PPT 的預覽圖同理是靜態的（動畫只在投影幕播）。
2b. **主 PPT 預覽會佔用一點時間**：每次換頁要匯出一張圖（0.2–1.3 秒），這段時間控制台可能微卡；頁碼沒變就不會重複匯出。
3. **只有一台螢幕（測試機常見）**：素材改用「只預覽不投出」——照樣可在控制台中央看到當前頁、用縮圖與翻頁筆翻頁，但**不開全螢幕素材視窗**，所以不會蓋住控制台；同時自動停用「控制台不搶焦點」，否則控制台切不回前台。放映仍會鋪滿整個螢幕，按 **Alt+Tab** 可切回控制台（已實測兩者互切正常）。
4. **黑屏會連放映一起遮黑**：素材蓋在放映之上，若只收素材會露出下面的 PPT，所以素材源下按黑屏會同時把 PowerPoint 設為黑屏；按「恢復畫面」兩者一起還原。
5. **導入素材不會自動切換**：新素材只加入左欄清單，要自己點卡片才會投出，避免聚會進行中一導入就換畫面。
6. **「加入主 PPT」只記住檔案位置，不會立刻開 PowerPoint**：真正開檔在按「開始放映」時，並自動等到 PowerPoint 準備好（最多 3 秒）才放映，避免「剛開檔就按放映」得到 `SlideShowSettings: Object does not exist`。主 PPT 仍由 PowerPoint 原生放映（保真、含動畫）；素材才是轉圖那條路。
7. **PowerPoint 被關掉會自動重建**：若簡報或 PowerPoint 視窗被關閉，COM 參考會失效（RPC 伺服器不可用）。程式會丟掉舊參考、重新建立 PowerPoint 實例並重開檔；若那檔案本來就在 PowerPoint 裡手動開著，則直接接管那個視窗，不會重開一份。

## 2026-11-10 實機除錯：四個根因與修法

以下四點都經本機實測確認，不是推測。

**1. 開簡報必須 WithWindow = -1**
`Presentations.Open(path, 0, 0, 0)`（無視窗開啟）會讓 `Presentation` 沒有文件視窗，`SlideShowSettings` 直接報 `Object does not exist`，放映永遠起不來。已改成 `-1`。

**2. 絕對不能在 Run() 之前設 StartingSlide**
這是「放映起來又立刻消失」的真正原因。實測：只設 `ShowType` 或加 `ShowWithAnimation` 或 `ShowWithNarration`，放映可穩定存活；一旦賦值 `StartingSlide`（設 1 或 2 都一樣），放映視窗不到 0.5 秒就自我結束。已改為啟動後用 `GotoSlide` 跳頁，起始頁為 1 時不跳。

**3. 放映視窗不能用 SlideShowWindow.HWND 定位**
該屬性在本機回傳空值。已改用 Win32 列舉視窗類別 `screenClass`；開啟「簡報者檢視畫面」時會同時存在兩個同類別視窗，以標題含「投影片放映」者為投影畫面、排除含「簡報者」者。

**4. 原始輸入要掛在主視窗，且不能靠在 UI 執行緒 Sleep 輪詢**
原本自建 0×0 隱藏視窗當 `hwndTarget`，`WM_INPUT` 收不到，綁定必逾時。已改掛主視窗 HWND（`WindowInteropHelper`），並移除 `Thread.Sleep` 輪詢——阻塞 UI 執行緒會讓 PowerPoint 建立放映視窗時卡住，這也是先前「放映視窗未出現」的另一半原因。日誌會印「原始輸入已就緒（目標視窗 0x…）」，綁定逾時也會附上期間收到的按鍵事件數，便於判斷是收不到還是不認得。

### 實測結果（本機）

- 放映視窗穩定停在第二螢幕並鋪滿，連按兩次「下一頁」頁碼 1 → 3；
- 「結束放映」二次確認按是後，放映視窗正確關閉；
- 原始輸入可收到按鍵事件。

### 追加：讓動畫在操作員操作時繼續播放（A + B）

**問題**：PowerPoint 全螢幕放映一旦失去視窗焦點，動畫就暫停——這是官方確認的設計行為。操作員在作業螢幕上點任何東西，投影幕的動畫就停住。

**A. 控制台不搶焦點**（右欄勾選「放映時控制台不搶焦點」，預設開）

放映啟動後，程式把自己的視窗加上 `WS_EX_NOACTIVATE`，並把前台還給放映視窗。此後點控制台按鈕不再改變前台視窗，PowerPoint 一直是前台，動畫不中斷。「結束放映」的二次確認、以及取消結束後，都會自動把這個樣式還原，否則對話框會拿不到焦點。

實測：用真實滑鼠點「下一頁」，頁碼 1 → 2，事後前台視窗仍是放映視窗（`0xB0D76`），不是控制台。

**B. 視窗化放映**（右欄勾選「視窗化放映（失焦仍播動畫）」，預設開）

改用 `ppShowTypeWsize`（PowerPoint 的「在視窗中瀏覽」），這是官方承認「失焦仍會繼續播放動畫」的唯一模式。代價是它天生帶標題列、不是全螢幕，所以程式用 Win32 把標題列與可拖曳邊框拆掉（`StripWindowFrame`），再 `SetWindowPos` 鋪滿投影螢幕。

實測：放映視窗為 `[7776,0,12096,2430]`（正好第二螢幕全幅）、`WS_CAPTION` 已去掉、標題仍為「PowerPoint 投影片放映 - [...]」。

**連帶修正**：視窗化放映的視窗類別是 `PPTFrameClass`，不是全螢幕的 `screenClass`。原本只認 `screenClass`，所以切到視窗化會報「找不到放映視窗」。現已改成同時接受「類別為 `screenClass`」或「標題含『投影片放映 / Slide Show』」的視窗，並排除標題含「簡報者 / Presenter」者。另外「找不到放映視窗」的失敗分支現在會先把已起來的放映關掉，不再留下沒人控制的放映視窗。

**限制**：兩個選項都只在「操作員用控制台」時保住焦點；若操作員真的切去用 Word／瀏覽器，A 就失效，要靠 B 讓動畫繼續。B 結束後 PowerPoint 會記住視窗位置，下次開同一份簡報可能直接開在投影幕上，程式每次都會重新定位。

### 追加：翻頁筆「結束投影後失效、換不了下一份 PPT」

**症狀**：綁好翻頁筆，播完一份、按「結束放映」，再開下一份 PPT 就怎麼樣都沒反應。

先照同樣順序但不綁筆、只用控制台按鈕走一遍：開 A → 放映 → 下一頁 → 結束放映 → 開 B → 放映 → 下一頁，全程正常。所以問題不在「結束後重開」這條流程本身，而在下面三件事之一，現已全部補上。

**1. 放映不是我們結束的，控制台會停在假狀態（最可能是這個）**

講員在投影幕上按 ESC、或直接在 PowerPoint 端結束放映時，程式原本不知道：`_running` 還掛著 true、`_showHwnd` 指向一個已經變回編輯視窗的舊視窗，而「不搶焦點」`WS_EX_NOACTIVATE` 也還留在控制台上。結果就是按鈕看起來能按卻沒作用，而且「開啟簡報」的檔案對話框叫不出來、搶不到前台，整個介面像死了一樣。

現在狀態計時器每 300ms 用視窗實際狀態校正：只要那個視窗的標題已不再是「投影片放映」（含視窗化模式的 `PPTFrameClass`），就判定放映已結束，自動把控制權、選單、`WS_EX_NOACTIVATE` 全部復原並記一行日誌。實測在投影幕按 ESC，約 1 秒內控制台回到「放映：未開始」，之後點「開啟簡報」對話框能正常跳到前台。

**2. 翻頁筆的「身分」比對太窄**

原本只認 `VID_xxxx&PID_yyyy` 這種 USB 寫法。藍牙筆的路徑是 `Dev_VID&02045e&PID&0237` 這種形式，取不到 VID/PID，只能靠完整路徑比對——換連接埠、重新連線、重新列舉一次就認不得，表現正是「昨天好好的，今天不動」。現在兩種寫法都會解析，統一用「VID + PID」當身分。

**3. 沒有日誌，看起來就像筆壞了**

現在每種情況都留痕，照這幾行就能直接判斷：

- `翻頁筆 → 下一頁，目前第 3 頁。`：筆有作用，一切正常
- `收到翻頁鍵 VK=0x22，但它不屬於已綁定的翻頁筆（本次裝置：VID_02045E&PID_0237），已忽略。`：收到了但裝置對不上 → 重新綁定
- `已收到翻頁筆按鍵，但目前沒有進行中的放映…`：筆正常，只是沒在放映
- `目前未綁定翻頁筆：講員按筆不會有反應…`：啟動時就告訴你綁定是空的
- `綁定逾時，未收到翻頁筆輸入（期間共收到 N 個原始按鍵事件）。`：N=0 是筆沒送訊號；N>0 是送了但不是上下頁鍵

**小功能**：簡報路徑可以當參數帶進程式（`ProjectionManager.exe "D:\...\簡報.pptx"`，或做個捷徑讓檔案拖上去），啟動就自動開好，省一次選檔。

### 使用前請先處理兩件環境問題

1. **關掉「簡報者檢視畫面」**：PowerPoint →「投影片放映」分頁 → 取消勾選「使用簡報者檢視畫面」。否則筆記型螢幕會另外跳出一個簡報者控制介面，佔著作業螢幕。
2. **第二螢幕要緊貼主螢幕右側、解析度用 16:9**：本機目前第二螢幕起始座標是 X=7776、決議 4320×2430，跟主螢幕（0–3456）之間有大空隙、比例也不符 16:9，屬於無線／虛擬顯示器的常見狀態，會讓投影位置與滑鼠鎖定的座標驗不準。

## 使用步驟

1. 確認 Windows 顯示設定為「延伸」，兩台螢幕都在清單中。
2. 按「重新整理螢幕」，選定投影螢幕（預設自動選非主螢幕那台）。
3. 按「綁定翻頁筆」，然後**按一下翻頁筆的下一頁鍵**，成功後顯示 `VID_xxxx&PID_yyyy`。
4. 按「加入主 PPT」（或直接點左欄那張「＋ 加入主 PPT（點此選檔）」卡片）選檔。**加入只是登記路徑，不會彈出 PowerPoint 編輯視窗**；按「開始放映」時才由 PowerPoint 開啟並直接轉放映。選過一次就會記住，下次開程式卡片已顯示檔名。
5. 勾選「鎖定鼠標在作業螢幕」。
6. 會前與過場由操作員點「上一頁／下一頁」推進；**操作員鍵盤按 PageUp/PageDown 不會翻頁**，避免邊做事邊誤動投影。
7. 講員上台時按「**交給講員**」：只是把狀態標示切成琥珀色並記錄交出頁；翻頁筆生效，操作員的按鈕**仍可用**。
8. 講員結束按「**收回控制**」：日誌顯示「交出時第 8 頁，現在第 15 頁」；要回原頁按「回到交出頁」。

**互不干擾靠這三條**：鼠標鎖在作業螢幕（碰不到投影）／操作員鍵盤不承擔翻頁／任何一次按鍵最多前進一頁。

## 沒有翻頁筆怎麼測

程式不看無線協定，只看「哪個裝置送出按鍵」。鍵盤與翻頁筆在系統裡同屬 HID 鍵盤，所以可以用鍵盤暫時充當翻頁筆，整條鏈路照樣走完：

1. 按「綁定翻頁筆」，然後**直接按鍵盤 PageDown**，綁定成功，顯示的即該鍵盤的裝置路徑。
2. 此後 PageDown／PageUp 就是「筆」的按鍵，可完整驗證：COM 推進、單次只前進一頁、放映有焦點時不重複、翻頁後頁碼同步。
3. 測完按「**解除綁定**」，回到正式狀態（只有控制台按鈕能推進）。
4. 重新綁定時只接受 PageUp／PageDown，誤按其他鍵不會綁錯裝置。

鍵盤充當翻頁筆時測不到的三件事，只有真筆能驗：換 USB 埠後 VID/PID 是否仍認得、無線延遲、以及筆休眠喚醒後首鍵是否被吞。

## 已知限制與可調點

1. **簡報以 `WithWindow=false` 開啟**（不彈出編輯視窗干擾操作員）。若放映視窗不出現，把 `PowerPointService.Open` 第四個參數由 `0` 改為 `-1`。
2. **簡報者檢視畫面**：請在 PowerPoint 關閉「使用簡報者檢視畫面」，否則放映可能被分割到作業螢幕。此為 PowerPoint 端設定，程式無法代關。
3. **裝置路徑不穩定**：同一支筆換 USB 埠會變路徑，程式已加 VID/PID 次要比對；換不同型號需重新綁定。
4. **啟動放映會短暫卡住**：`StartShow` 在同一條 STA 執行緒等待放映視窗出現（最多 3 秒）。M2 改為非阻塞。
5. **操作員鍵盤不承擔翻頁**：只有「已綁定的裝置」與控制台按鈕能推進。若把鍵盤本身綁定成翻頁筆（測試用），它就按「筆」對待，此時全鍵盤的 PageUp/PageDown 都會翻頁，記得測完解除綁定。
6. **已移除 B 鍵切黑屏**：因鍵盤可能被綁成筆，誤按 b 會讓投影突然變黑。黑屏請用控制台按鈕。
7. **匯出素材會卡住界面**：同前言第 1 條，同步 COM 轉圖。
8. **素材不保真動畫**：只匯出靜態頁面。
9. **分組的重新命名／刪除只驗過程式路徑，未做端到端點擊測試**：新增分組、單檔導入、整批資料夾導入均已實測；右鍵選單的兩項尚未在實機點過，若操作異常請回報日誌。

## V1.2 經文投影：新增了什麼

左欄按「＋ 經文　（書卷／章／節）」開啟選擇視窗：書卷（66 卷和合本）、章、節範圍（起～迄）、字級（32–72 pt）、樣式（深底白字／淺底深字）、是否顯示節號。按「投影」即加入左欄「經文」區並立刻播出。

- 經文資料是**公版和合本（CUV）**，已離線打包在 `Assets\bible_cuvt.json`（繁體，66 卷／1189 章／31031 節），投影時**不連網**。
- 投影畫面由程式自己排版：深/淺兩種主題、微軟正黑體、1.5 倍行高、固定邊距；右上角是出處（例：約翰福音 3:16-21），右下角是頁碼。
- **自動拆頁**：以實際字高量測，不是按字數估算。一頁放不下就換頁；單節比整頁還高時（長節）會按字切塊續頁，不會被截掉。字級改大、投影螢幕解析度不同，都會重新排版。
- 每條經文是一張卡片，右鍵可「從左欄移除」；相同書卷章節再次加入時只更新字級／樣式，不會重複堆卡片。
- 翻頁筆（或控制台「上一頁／下一頁」）在經文源就是換經文頁；縮圖條會列出經文頁碼，可直接跳頁。
- 只有一台螢幕時，經文**只在控制台中央預覽整段經文**，不開投影視窗（避免蓋住控制台），日誌會寫明。

## V1.3 網頁投影：新增了什麼

左欄按「＋ 網頁　（瀏覽器投影）」輸入名稱與完整網址（http/https），加入後立刻播出。使用 **WebView2**（Edge 內核，本機已安裝 Runtime 157）全螢幕鋪在投影螢幕上，無邊框、置頂、不搶焦點。

- 右欄「網頁控制」提供「重新載入」「上一頁」「下一頁」（瀏覽器歷史，不是投影源切換）。
- 翻頁筆在網頁源＝上下滾動一屏（約 80% 視窗高），適合長歌詞、長文章。
- 網址清單存在 `%AppData%\ProjectionManager\web_links.json`，重啟後仍在；右鍵可移除。
- 只有一台螢幕時只顯示網址與說明，不開投影視窗。

## V1.4 Zoom 投影：新增了什麼

左欄固定有一張「Zoom 會議投影」卡片（在「Zoom」區）。按它（或左下「Zoom 投影」按鈕）會找出 Zoom 進程中面積最大的可見視窗，去掉標題列與邊框，鋪滿投影螢幕並置頂、不搶焦點。切換到任何其他投影源時，Zoom 視窗會**自動還原**成原本的樣式與位置（右鍵也可手動「還原 Zoom 視窗」）。

現場流程（與需求一致）：

1. Zoom 會議中「分享螢幕 2」，線上會眾看到投影幕畫面；
2. 把 Zoom 主持權／分享權交給線上講員；
3. 在 Zoom 裡取消「螢幕 2」分享；
4. 回到控制台點「Zoom 會議投影」，Zoom 會議視窗鋪到螢幕 2 —— 現場與線上同時看到線上講員的分享；
5. 講員結束後，點主 PPT 卡片切回，Zoom 自動還原。

本程式**不改 Zoom 的分享設定**：分享哪個螢幕仍要在 Zoom 裡自己選（Zoom 是否記住上次分享的螢幕，需在真實會議驗證）。

## V1.2–V1.4 的已知限制

## V2.0：手機遙控器（瀏覽器免安裝 App）

**用途**
- 手機與電腦連同一個 Wi-Fi，用瀏覽器打開控制台顯示的網址，輸入 6 位配對碼，即可當一支「翻頁筆」：上一頁／下一頁、跳頁、黑屏／恢復、切換投影源、結束放映。
- 不做系統層 HID 冒充，也不模擬鍵盤；所有指令都走應用層 HTTP，和實體翻頁筆互不干擾。

**啟動與配對**
- 控制台右欄「控制者」分區新增「手機控制…」按鈕（非模態視窗，開著也不擋控制台）。
- 視窗顯示：服務狀態、可複製的網址（例 `http://192.168.0.170:5180`）、大字配對碼、「啟動手機控制」勾選、「更新配對碼」、已綁定手機清單。
- 服務預設埠 5180；配對碼每次啟動重新產生（6 位數字）。手機第一次輸入配對碼後取得一組 token，存在手機 localStorage，之後打開網址免再輸入。
- 裝置上限 5 台；清單可切換角色、可撤銷（撤銷後該 token 立即失效，需重新配對）。

**角色綁定**
- 操作員（全部控制）：上下頁、跳頁、黑屏／恢復、切換投影源、結束放映。
- 講員（只上下頁）：只允許 `next`／`prev`，其他指令回 403「講員端只允許上下頁」；手機頁面也不顯示投影源清單。
- 角色切換即時生效，存在 `settings.json` 的 `MobileDevices`。

**指令對應**
- `next`／`prev`：主 PPT 走 PowerPoint 原生翻頁；素材走內建圖片翻頁；經文走拆頁翻頁；主 PPT 尚未放映或空白時回「主 PPT 尚未放映」，不會假成功。
- `goto`：主 PPT 用 `GotoSlide`、素材直接跳頁；經文回「請用上下頁」。
- `black`／`resume`：與控制台「黑屏」「恢復畫面」同一套邏輯。
- `stop`：直接結束放映，不彈確認框，控制權交回操作員。
- `source`：切換投影源（僅操作員）。

**去抖與連線**
- 手機頁面每 900 ms 輪詢一次狀態；頁面不可見時暫停輪詢。
- 同一支手機、同一方向 260 ms 內的重複點擊回「已略過重複點擊」；`next` 與 `prev` 分開判斷，不會互相誤擋。
- token 失效（401）時手機頁自動回到配對畫面。

**已知限制**
1. 首次啟動 Windows 會彈「防火牆是否允許存取」；要用手機連線必須按「允許」（專用網路即可）。按「取消」或關掉提示，手機就連不上，但本機 `127.0.0.1` 仍可用。
2. 手機端頁面已用 430×932 瀏覽器視窗驗證版面；真機 Safari／Chrome 尚未實測。
3. 目前只有 HTTP 輪詢，沒有 WebSocket；操作延遲約 0.3–1 秒。
4. 同一區網若有 AP 隔離（用戶端隔離），手機與電腦互相看不到，需在路由器關閉該功能。
5. QR code 尚未實作（規劃在 V2.1），目前用「複製網址＋輸入配對碼」。

**本機已驗證（單螢幕、loopback 與區網網址）**
- `GET /` 回 200（8,495 bytes）；未帶正確 token 的 `GET /api/state` 回 401。
- 由控制台讀取配對碼後 `POST /api/pair` 成功，取得 64 位 token 與 role=operator。
- 重啟程式後用同一 token 仍可取得狀態（deviceName 保留）→ 裝置綁定持久化有效。
- 空白主 PPT 時 `next` 回 `{ok:false,"message":"主 PPT 尚未放映"}`；狀態列主 PPT `live=false`、名稱顯示「尚未加入主 PPT」。
- 切到素材 `Presentation 3`：`page=1 total=13`，`next` → 2、`goto 5` → 5、`prev` → 4；`black`／`resume` 正常。
- 講員角色：`sources=[]`、`goto` 與 `black` 回 403、`next` 仍可送；切回操作員即恢復。
- 去抖：連續兩次 `next` → 第一次「已下一頁」、第二次「已略過重複點擊」，頁碼只前進 1。

## V2.1：預覽／頁數／跳頁修正＋測試模式

**本輪修正（主 PPT 原生放映中）**
- 頁數不再依賴匯出：預覽卡右下角新增頁碼徽章「第 x / N 頁」，只看放映狀態；標題列固定顯示「主 PPT　第 x / N 頁」。匯出失敗時頁數照樣在。
- 預覽圖改「先更新介面、再排隊匯出」：換頁先更新頁碼與標題，圖片由 `DispatcherPriority.Background` 排隊匯出；新圖未好時保留上一張，不再清空。匯出失敗 1.5 秒後自動重試。
- 大幅跳頁卡頓：換頁不再整條重建縮圖，只更新目前頁的高亮框（`UpdateThumbHighlight`）；換頁只跑 `RenderPreview + UpdateThumbHighlight`。控制台、縮圖、手機三條路徑共用。
- 新增跳頁輸入：翻頁列加「跳到 [ ] 頁 · 跳至 · 末頁」，Enter 直接跳；越界只寫日誌、不拋例外；手機 `goto` 也走同一個 `TryJumpToPage`。

**測試模式（單螢幕也能跑雙螢幕流程）**
```powershell
# 以 Debug 版為例；--auto-show 會自動開始放映
.\bin\Debug\net8.0-windows\ProjectionManager.exe --test-mode --auto-show "D:\...\Presentation 3.pptx"
```
- `--test-mode`：把主螢幕右半模擬成「螢幕 2」（`\\.\TEST2`），投影目標自動選它；控制台可自行移到左半，不必 Alt+Tab。強制視窗化放映，動畫在失焦時仍會播放。
- 手機服務只綁 `127.0.0.1`，不會跳 Windows 防火牆提示；控制台標題顯示 `投影控制台（測試模式 PIN xxxxxx）`，供自動化讀取。
- 測試模式另開 `POST /api/test/role`（僅 test-mode＋loopback 生效），讓自動化切換操作員／講員，不必操作「手機控制」視窗。
- 設定檔可用環境變數 `PROJECTIONMANAGER_SETTINGS` 指向暫存檔，測試不會污染 `%AppData%\ProjectionManager\settings.json`。

**自動化測試**
```powershell
powershell.exe -ExecutionPolicy Bypass -File .\tests\Run-TestMode.ps1
```
- 產出 `tests\測試結果_自動化.md` 與 `tests\artifacts\*.png`。
- 本機（主螢幕 3456×2160，模擬螢幕 2 = 右半 1728×2160，Presentation 3 共 13 頁）：V2.1 基線 **23 / 23**；V2.2 全功能 **41 / 41**（明細見下）。
- 覆蓋：模擬螢幕定位、放映狀態、頁碼徽章、靜態預覽圖（13,589 B 真實畫面）、跳 10／13（724 ms／247 ms）、越界 14 不崩潰、13↔1 來回四次最慢 72 ms、手機上下頁／跳頁／黑屏／恢復／切源／講員 403／401／錯誤 PIN／去抖。

**測試模式的邊界**
- 模擬螢幕是同一個實體螢幕的右半，不是真正的第二輸出：能驗證視窗定位、頁碼、預覽、指令與狀態，但不能驗證「投影幕解析度不同」「實體翻頁筆」「PowerPoint 動畫在真實延伸螢幕上的流暢度」。
