## 四、判定與建議

- 全部門檻達標。控制台在待機與高頻操作下沒有出現 CPU 持續高佔用、記憶體大幅累積或控制代碼暴增。
- 高頻跳頁時控制台全機 CPU 6.06%，單核 96.9%；目前延遲仍低，但 UI 執行緒幾乎滿載，動畫較多或較慢的機器上仍有卡頓風險。
- 門檻由本次測試設定（例如待機 CPU <5%、記憶體增量 <150 MB），不是產品規格；可依實際驗收標準調整。
- 已知限制：主 PPT 每次換頁會同步匯出目前頁預覽，換頁延遲與頁面內容複雜度、PowerPoint COM 狀態有關；本測試在同一台機器、同一份 13 頁簡報上量測。
- 「流暢」以操作延遲與 CPU 佔用判定，未量測投影幕實際 FPS；真雙螢幕動畫流暢度仍需硬體驗收。
- 按鈕延遲以按鈕共用的 Navigate() 路徑（next／prev）量測；本測試會話沒有可互動桌面（SetCursorPos／SetForegroundWindow 均失敗、前景視窗代碼 0），UIA Invoke 會多出約 2 秒跨進程等待，因此未把兩者當作畫面延遲。
- 記憶體取工作集（Working Set）；壓力後先靜置 20 秒再取穩定值，避免 GC 時機造成單點偏高。
- 記憶體增量 Δ54.6 MB，已低於 150 MB 門檻；快速切源峰值 352.2 MB，靜置 20 秒後回落到 272.5 MB，未見持續累積。素材縮圖改以 480px 解碼並與整頁圖分開快取（整頁 8 張、縮圖 24 張），是本次改善的主因。
- 本輪同時修正 4:3 簡報被固定匯出成 16:9 的問題：4:3 預覽圖為 768×576（1.333），16:9 來源仍為 1024×576（1.778），兩者都完整顯示、不變形。
